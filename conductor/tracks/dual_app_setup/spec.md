# Dual App Setup Spec

## Overview
Due to CoreML deployment challenges on the physical iOS device, the vision pipeline has been restructured. The Desktop version of the Tauri application will run the ONNX inference model and stream the resulting bounding boxes through the Raspberry Pi WebSocket gateway to the iOS app in real-time.

## Requirements
- `gateway.py` on the Raspberry Pi must maintain a state of all connected WebSocket clients.
- When `gateway.py` receives a `{"type": "bounding_boxes", "boxes": [...]}` message, it must broadcast it to all other connected clients.
- `websocket.rs` on the Desktop must extract bounding boxes from local ONNX inference and send them to the gateway as `{"type": "bounding_boxes"}`.
- `+page.svelte` on the frontend (specifically for the iOS client) must listen for Tauri `json-message` events, check for the `bounding_boxes` type, and update its local `boundingBoxes` state to visualize the boxes generated by the desktop.
- `gateway.py` must track LED mode globally so the animation loop runs correctly within the continuous telemetry frame.
